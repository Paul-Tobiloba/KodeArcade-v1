# Teacher learning progress extension

Mode: Operate. Code-led extension of the existing classroom-management surface; preserve DESIGN.md, brand, typography, account shell and roster behavior. No new visual world or raster assets.

THESIS: Teachers can see saved learning results for their own class and choose a student for a helpful conversation.

OWN-WORLD: Existing purple/lavender account interface, Fredoka headings, plain readable tables, restrained native form controls and original K logo.

STORY: Classes → class → Learning progress → assigned course/filter → student challenge details. Mutating credentials still require recent adult verification; read-only reports use verified teacher/class authority.

FIRST VIEWPORT: The existing classroom header remains primary. Learning progress joins below class metadata, with course selection and Refresh progress followed by an actual result table. Horizontal overflow stays inside tables on phones; the page itself must not overflow.

FORM: Table columns: student, completed challenges and drawings, best stars, last activity, check-in, last saved and details. Details expose challenge completion, stars, runs and hints, never credentials or raw saved code. Empty, loading and failure states explain next actions.

QUALITY BAR: Desktop, phone and tablet; readable table headers; labeled selects; keyboard-scrollable tables and clear focus; server-scoped enrollment/assignment checks. Check-in signals mean unfinished challenges with 3+ runs or 2+ hints, not a diagnosis or proctored assessment. Synthetic screenshots must be labeled as verification data.

FINISH: Independent screenshot/source review and documentation comparison with the incumbent system. Do not rewrite global design files for this local addition.
