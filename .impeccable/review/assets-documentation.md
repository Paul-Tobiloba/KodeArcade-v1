## Implemented feature truth and boundaries

The current top entry of `PRODUCT.md` and the asset implementation notes agree with the inspected extension. The catalog is deliberately separate from guided-course mascots. Its fifteen sprite choices and nine backdrop choices extend the prior seven/four; projects still allow at most four sprites and 24 assets. Choosing a new sprite creates its own blank editable script, while choosing a costume changes the selected sprite's costume list. There is no claim of unrestricted Scratch compatibility or new formal Events coverage.

Backgrounds → Import image accepts local PNG, JPEG or WebP up to 5 MiB. `studioImageImport.ts` rejects empty/unsupported/oversized files, dimensions beyond 16 million pixels or an 8,192px edge, and decode failures. It uses a temporary object URL, draws local pixels onto white, and tries bounded JPEG encodings at maximum edges 768/512/384 and qualities .8/.6/.4. It returns only a Data URL accepted by the 80,000-character validator, then revokes the temporary URL. Source dimensions preserve aspect ratio; the filename, original bytes and metadata are not put into the project. Transparency is flattened to white and animated input becomes a still copy. GIF/SVG and arbitrary URL import are not supported.

`studioProject.ts` permits an `image` asset only with background purpose, a bounded base64 PNG/JPEG/WebP Data URL and no library reference. A drawing background may retain that validated image as its base. Catalog references remain allowlisted. Single-project JSON is bounded to 240,000 characters; the collection's twenty-entry/600,000 UTF-8 byte budget remains, including Recently deleted. Imported images and editable image copies consume those existing bounded budgets. Editor Open now accepts a 2 MiB input file before schema validation, matching the documented gallery file-input ceiling; the previous gallery report's narrower editor-file ceiling is historical.

`CreativeStudio` decodes before constructing and committing the replacement background; failed validation or parent capacity rejection leaves the last valid project intact. Cancelling a picker produces no change. Leaving/unmounting the editor before decode completes prevents that import's late commit. Image assets can be renamed, duplicated, removed or used as the basis of a private painted copy through existing controls. The image is embedded in project/gallery backups, rather than uploaded to an external asset service.

The asset-dropdown repair is functional, not a visual-system change. Both `StudioEditor` and `StudioEngine` set a per-workspace asset context before Blockly deserialization. `studioBlocks.ts` includes actual image/drawing backgrounds in choices and retains stale authored IDs as Missing asset; runtime rejects an unavailable background instead of silently substituting another selection. Category colors and real connected Blockly geometry are retained.
