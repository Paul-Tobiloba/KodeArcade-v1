## Confirmed behavior and limits

Design offers seven actual controls: button, label, text input, text area, dropdown, checkbox and slider. Controls can be added by tap or drag, selected, moved by pointer or arrow keys, and edited through properties. Shift-arrow moves by ten units. Run uses the same framed preview, while Stop/Reset returns to the authored state. Screens, controls, starting values and local tables remain part of the project.

The independent structured editor packs and unpacks the existing `AppCode`/`AppBlock` model. It provides editable command heads, nested onStart/onEvent/if/repeat bodies, drag movement/insertion, tap-selected insertion points, deletion and mounted-session undo/redo. Command-head editing preserves the command type and accepts argument changes; it is not expression-socket dragging or the Droplet library.

The lazy-loaded CodeMirror editor provides JavaScript highlighting, line numbers, wrapping, a lint gutter, syntax/reference diagnostics and supported-command plus screen/control/table-ID completion. Ctrl+Space opens suggestions. `appLabDiagnostics.ts` detects parser errors, absent referenced controls/screens/tables/columns, unattached commands and variables never assigned anywhere. This is not path-sensitive verification: a declared variable may still be read before assignment at runtime. Block warnings are contextual disclosure rows and a bounded visible issue list.

Acorn parses a documented JavaScript subset into allowlisted blocks. Supported operations include click/change events, startup commands, screen/text/visibility changes, initialized var/let or assignment, print, if/else, bounded repeat, supported expressions and project-local data reads/updates. No source is evaluated as JavaScript. The runtime dispatches known block types and checks types, references, numeric bounds, missing rows, zero division and execution limits. Variables are app-wide, including callback declarations. This does not implement general JavaScript, arbitrary methods, browser/network APIs, async/imports, user functions, canvas/turtle, media, charts, public publishing, a shared database or full Code.org compatibility.

Typed drafts save separately under optional `codeDraft` (20,000 characters). Apply parses, validates and normalizes into the shared block program; formatting/comments are not retained in that model. Discard restores applied code. Both the UI and runtime refuse Run while a draft exists. Existing projects open using the retained bounded model rather than being automatically converted destructively. Current shared validation allows eight apps per gallery, six screens, forty controls, 120 connected/value blocks per project, six tables with fifty rows/eight columns each, and bounded nesting/data size. Runtime limits include 1,000 steps per execution, 10,000 per run and 500 events.

Public preview remains browser-local; student work uses the existing private account/recovery integration. The optional draft field requires coordinated frontend/backend deployment. No migration or production operation is performed by this documentation pass. App Lab is unscored; the revision makes no curriculum, reward or learning-outcome claim.
