# Grade 3 App Lab practical — 21 October 2026

This additive pilot unit is **Build a greeting app and click counter**. It does not replace existing Grade 3 missions, reorder course IDs, or claim completion of the whole curriculum enhancement.

## Learning sequence

1. Predict a greeting and counter result, and explain the input/click relationship.
2. Investigate the actual running app using several pretend nicknames, repeated clicks and reset.
3. Modify the greeting prefix while retaining its input connection.
4. Repair a wrong initial value, wrong event and reset that changes the label but not the variable.
5. Adapt the counter to add two points per click.
6. Reconnect a fresh app with changed control IDs and a different prefix/increment. A conceptual hint makes this a supported check, not new independent mastery.

Completing all five practice steps earns one five-star result. Hints/retries never reduce that practice reward. Independent evidence is reported separately and monotonically preserved. Checks execute the real bounded App Lab program across different inputs, an empty input, repeated clicks, reset/next click and unrelated-output preservation. They do not match a single source string, evaluate arbitrary JavaScript, or establish general coding competence.

## Implementation and storage

`AppPractical` reuses App Lab's actual JavaScript-shaped stackable blocks, numbering gutter, editable text parser, preview and allowlisted runtime. The supplied one-screen design is fixed for this code-led unit; this is not a full screen-design course. The existing App Lab palette remains available. Personal App Lab projects stay in their separate gallery and are not overwritten or automatically copied by the lesson.

Six authored project drafts and prediction responses are saved under the separate version-1 Grade 3 `appPractical` progress field. Public preview key: `kodearcade-app-practical-v1:grade-3`. Private records use the assigned learner/course scope. An old client omitting the optional field preserves existing evidence; cross-grade and unassigned access are rejected. Grade 2/4 `practical`, typing and core course totals remain unchanged. Frontend and API validation should be released together; no database migration is required.

The validator bounds record size/depth/nodes, project size (30 KB), six drafts, one home screen, twelve controls, no data tables and the existing App Lab code limits. Unfinished text survives reload but cannot run until applied. Malformed originals are preserved with recovery download; storage failures retain the open work and offer retry/backup. Visible private navigation flushes or requires backup before leaving.

Live preview nickname input is temporary and is not written back to the project. **Authored code and control text do persist** in drafts, so use pretend details. No uploads, voice, network requests or teacher submissions were added.

Completion uses a native centered modal, backdrop, Escape/close and focus return; practice and independent-check dialogs are distinct. Device reduced motion and the unit's mounted session setting disable reward motion; that local toggle is not saved. Small devices stack the preview and editor; the desktop toolbox and program scroll internally within the bounded editor.
