## Blocks and typed code

The independent structured block editor replaces Blockly only in App Lab. It displays JavaScript-shaped onStart/onEvent containers, editable command lines, nested if/else/repeat bodies, category commands, insertion points, drag placement/movement, deletion and session undo/redo. Tapping an insertion point and a command provides a non-drag insertion route. Arguments accept supported expressions. It is not the Droplet library and does not promise all Droplet interactions, expression-socket dragging or Code.org compatibility.

Show text opens CodeMirror, with JavaScript syntax highlighting, line numbers, lint gutter/underlines, supported-command and Design/Data-ID completion (Ctrl+Space), and visible diagnostics. Blocks show contextual line warnings too. Acorn parses text, and a whitelist converter produces the same bounded AppBlock data used by old projects. No source is eval'd or passed to a Function constructor. The code editor and completion assets are local dependencies; CodeMirror is lazy-loaded when text view is opened.

Supported actions: onStart, onEvent with click/change, setText, setScreen, showElement/hideElement, initialized var/let or assignment, console.log, if/else, repeat(count, function() {...}), and local setCell. Values include quoted text, finite bounded numbers, booleans, variables, +/−/*//, equality/inequality, >/<, &&/||, getText/getNumber/getChecked, joinText, getCell and getRowCount. getVariable/setVariable preserve old variable names that cannot be emitted as ordinary JavaScript identifiers. disabled/unattached wrappers preserve non-running saved blocks during text conversion.

This is a teaching subset, not general JavaScript. Variables are app-wide even when declared in a callback; arithmetic follows the existing numeric runtime, and joinText explicitly joins text. Repeat is a bounded helper, not a general for/while implementation. No browser objects, arbitrary methods, network, async, imports, arrays/objects, user functions, camera/microphone, canvas or turtle APIs were added. Completion suggests only supported commands; it does not imply other Code.org APIs exist.

## Drafts, diagnostics and compatibility

Valid text is applied explicitly. Apply validates and normalizes supported code into blocks; comments/formatting are not retained in that normalized model. An incomplete or unsupported draft is stored separately under optional codeDraft (20,000 characters maximum), including in gallery backups/private progress. Run is disabled until the draft is applied or discarded. Discard restores the last applied program. Runtime independently refuses a project carrying an unresolved draft, including one imported without the UI.

Syntax and unsupported-language errors identify the affected source line. Static checks flag missing control/screen/table/column references and variables never set; they do not prove path-sensitive correctness. The bounded runtime still checks wrong types, unset variables, missing rows, zero division and step limits. Applied typed commands carry line metadata for runtime errors. Existing project code stays intact on opening; no automatic destructive conversion occurs. All first-release gallery/project bounds and account ownership checks remain.

The frontend/backend must deploy together for account saves containing the optional draft field. No migration, new service, production database operation, push, merge or deployment occurs in this pass. Public work remains browser-local and separate from student account work. Curriculum integration remains on hold.
