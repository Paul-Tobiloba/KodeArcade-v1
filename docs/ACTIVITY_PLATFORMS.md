# Task-specific stages in the shared learning workspace

Owner direction, 9 October 2026: keep one consistent learning interface, navigation, Blockly palette, code canvas and Play below the stage. Tasks change the execution stage and task-specific blocks/commands where needed. The supplied code.org screenshots guide arrangement, not an exact composition. Character art supports the teaching mechanics.

## Implemented

- Route platform: character/grid, Blockly or Grade 5–6 typed instructions, route playback and runtime state. Existing conditions and numeric-score routes still use this platform; a different backdrop does not make them a new platform.
- Drawing stage: smooth white paper replaces the grid inside the incumbent workspace-grid/scene/editor shell. Dash the rabbit holds a pencil and moves as ink appears; a small direction pointer and dotted target support the task. Shared BlockEditor/TextEditor, draggable palette/code canvas, navigation, under-stage Play/Stop and clear controls remain. Ink and width tools open on demand. There are 34 activities across six grades (5/5/6/6/6/6), with independent drafts, mode, tool choices, completion and protected best 1–5 practice stars. Early controls are arrows with numerals, middle grades introduce angle/repeat work, later activities use changing distances, pen lifting and saved branch positions. Practice stars do not add core stars or confer core mastery/badges. Dendrites are stylised geometry, not ice-physics simulations or arbitrary recursive Python. Sprite provenance: DRAWING_ASSET.md.
- Computer Explorers: existing mouse/touch drag-and-drop and keyboard activities, independent of robot routing.

## Planned, not available yet

- Sorting/conditions: objects, bins and decision rules; execute the rule against examples and explain the classification.
- Events: actor stage with click/touch/key triggers and visible reactions; learners wire events to actions.
- Variables/state: counters, inventories or a small shop/lab; store/change/read values and watch state evolve.
- Game creation: an actor scene, collisions, scores and project controls rather than a larger route grid.

Future stages must fit the shared learning shell while providing objective mapping, age-appropriate inputs, accessible equivalents, runtime limits, feedback and assessment evidence. Existing completion must not be reinterpreted as mastery of new mechanics. The first complete-flow Grade 1 Sequences journey and optional drawing practice do not complete the full V2 curriculum.
