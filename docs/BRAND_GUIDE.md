# Brand Guide

## Brand name

**KodeArcade**

The name combines coding with the energy, progression, and immediate feedback associated with an arcade. It positions learning as active creation rather than passive study.

## Brand essence

**A welcoming playground where young learners turn logic into things they can see, control, and share.**

## Tagline

**Play. Build. Learn.**

## Brand promise

Every learner should be able to experience an early win, receive useful help when stuck, and leave knowing what to try next.

## Positioning statement

For young learners beginning their coding journey, KodeArcade is an accessible, game-inspired learning platform that turns programming concepts into interactive missions and creative projects. Unlike a static lesson library, it supports persistence through progressive hints, saved progress, and clear, explainable next steps.

## Brand personality

- **Playful, not childish**
- **Encouraging, not patronizing**
- **Energetic, not distracting**
- **Smart, not intimidating**
- **Inclusive, not one-size-fits-all**

## Voice and tone

### Use

- Short, direct instructions
- Encouragement tied to effort or strategy
- Specific feedback about what happened
- Language that normalizes mistakes and help-seeking

### Avoid

- “That was easy.”
- “You failed.”
- Excessive exclamation marks or forced slang
- Comparisons with other learners
- Claims that points or speed equal intelligence

### Example interface copy

| Situation | Preferred copy |
|---|---|
| Program does not reach the goal | “Your program stopped one square early. Check the final movement block.” |
| Learner requests help | “Good call. Let’s look at what the loop repeats.” |
| Learner completes a mission | “Nice work—you used a loop to solve the route with fewer blocks.” |
| Returning learner | “Welcome back. You were practising conditions. Here’s a quick recap.” |

## Visual direction

The interface should feel like a modern creative game, not a casino arcade. Avoid flashing elements, slot-machine imagery, manipulative reward patterns, and visual overload.

### Working colour palette

| Role | Colour | Hex |
|---|---|---|
| Primary dark | Midnight | `#111827` |
| Primary action | Electric violet | `#6D4AFF` |
| Progress/success | Arcade teal | `#0F9F8F` |
| Highlight | Solar yellow | `#F6C445` |
| Warm accent | Coral | `#F26B5E` |
| Surface | Cloud | `#F7F8FC` |
| Main text | Ink | `#172033` |

Every colour combination must be tested for accessible contrast. Success, warning, and error states must also use icons and text rather than colour alone.

## Typography

- Prefer an accessible, highly legible interface typeface such as **Atkinson Hyperlegible** when it can be bundled efficiently.
- Use a rounded display face sparingly for headings or the wordmark.
- Provide system-font fallbacks to reduce loading cost.
- Avoid using stylized display text for instructions or code.

## Logo direction

Start with a simple wordmark. A future symbol could combine:

- two interlocking code blocks;
- a cursor or play triangle;
- a subtle arcade-button or directional-pad shape.

The mark must remain recognizable in one colour and at favicon size. Avoid a detailed mascot inside the primary logo.

## Product vocabulary

| Product concept | KodeArcade term |
|---|---|
| Course group | World |
| Lesson | Mission |
| Exercise | Challenge |
| Final assessment | Build Project |
| Hint system | Power-Up |
| Progress overview | Journey Map |
| Skill indicator | Skill Meter |
| Recommendation | Next Move |

Use game vocabulary only when its meaning is immediately clear. Pair unfamiliar terms with plain-language labels during onboarding.

## Ethical engagement rules

- Rewards acknowledge learning; they do not conceal learning goals.
- No loot boxes, random paid rewards, or artificial scarcity.
- Streaks must not punish learners for limited access.
- Leaderboards are excluded from the proof of concept.
- Notifications are minimal and never designed to create anxiety.
